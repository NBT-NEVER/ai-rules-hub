# Recall Rules

## 定位

- 本文件是长期经验库，用于在执行任务前、中、后随时调用，而不是只在反思总结时读取。
- 重点保存可复用的坑点、稳定做法、核验方法和触发条件。
- “如何维护 skill 体系”以及“如何把新经验写回 skill”的流程不放在这里，那部分归 `C:/Users/18030/.codex/skills/skill-maintainer`。

## 何时优先读取

- 涉及 `.docx`、图表替换、段落/表格/图片混排定位时。
- 涉及 `.tex`、`.bib`、`.cls`、`.sty`、LaTeX 模板复制、编译验证或 PDF 输出核验时。
- 涉及 `pdf`、`word`、`ppt`、`txt` 等文件读取、抽取、转码及其中间文件落地时。
- 涉及中文写回、编码判断、BOM 处理、PowerShell 执行链路时。
- 涉及高价值文件覆盖、批量替换、需要先备份再改时。
- 涉及结果核验、图片/表格/正文一致性检查时。
- 涉及明显可能复用过往踩坑经验的任务时。

## 使用方式

1. 先判断当前任务与哪类已有经验最接近。
2. 在真正执行写入前，先套用对应小节中的预防动作与核验动作。
3. 发现已有经验能覆盖风险时，优先沿用稳定路径，不重复试错。
4. 如果当前任务暴露了新坑或修正了旧经验，再由 `skill-maintainer` 负责把新经验回写到本文件。

## 快速应用清单

- 先看有没有对应的踩坑点。
- 再看正确做法是否能直接套用。
- 执行前明确核验方法，不要等失败后再补检查。
- 修改高价值文件时默认先备份。

## 当前长期经验

### Word 文档读取与定位

- 处理 `.docx` 时，优先使用 `python-docx` 读取段落、表格和图片结构，不要把它当普通文本文件处理。
- 当结果区同时存在段落、表格和图片时，不能只靠 `doc.paragraphs` 的索引猜结构。应额外建立 block 级遍历，区分段落和表格的实际顺序。
- 要定位某一节中的图片，不要只看标题文字。应结合段落 XML、`w:drawing`、关系目标或 `word/media` 内容核对真实插图位置。

### Word 文档写入与替换

- 修改 `.docx` 前先备份原文件，尤其是在需要替换图片、表格和大段正文时。
- 如果文档已经被错误写入污染，优先从备份版重新构建目标修改，而不是继续在污染结果上叠加修补。
- 替换图、表、正文后，至少做三层核验：结构位置是否正确、数值文本是否一致、嵌入媒体是否真的是目标文件。

### LaTeX 源文件写入与编译

- 处理 `.tex`、`.bib`、`.cls`、`.sty` 时，优先把它们当作 UTF-8 源文件，不要先转成 Word 风格的中间文本。
- 修改 LaTeX 模板前先复制模板或备份源文件，再在工作副本中改；不要直接改导出的 PDF 或编译产物。
- 中文 LaTeX 场景里，先确认模板编码、编译引擎、字体方案、参考文献工具和主入口文件，再动正文。
- 如果模板已经稳定，尽量保持宏命令、结构层级、引用命令和资源目录不变，只向现有槽位填入内容。
- 编译验证优先处理第一处 LaTeX 报错，再看缺失资源、未定义引用、参考文献失败、目录或图表编号异常。
- 如果终端日志和最终 PDF 表现不一致，分别核验源码字节、编译日志、PDF 渲染结果，不要把显示层乱码直接当作源文件损坏。

### 中文写入与编码链路

- 在当前 Windows PowerShell 环境中，不要把包含大量中文的 Python 脚本通过 heredoc 直接传给 `python -`。这条链路可能把中文替换成 `?`，并把污染写进目标文件。
- 需要执行包含中文的大段脚本时，优先用 `apply_patch` 创建 UTF-8 文件，再运行该脚本。
- 读取可能带 BOM 的 CSV、txt 或 Markdown 时，优先考虑 `utf-8-sig`，避免把 BOM 字符继续写回 Word、Markdown 或配置文件。
- 终端显示乱码不等于文件已经损坏。先看真实码点、`unicode_escape` 或明确的编码读写链路，再判断是不是文件内容坏了。

### 文件写入与回写策略

- 对高价值文件，不要一上来就原地覆盖。先备份，再改，再核验，再决定是否保留辅助脚本。
- 修改后要检查“文件真实内容”和“展示层表现”是否一致。只看终端显示不足以确认写回成功。
- 临时脚本完成任务后应及时删除，避免把一次性修复工具长期留在规则目录或工作目录中。

### 文件读取临时目录管理

- 读取 `pdf`、`word`、`latex`、`ppt`、`txt` 等文件时，如果需要中间转换文件、抽取结果、缓存图片或结构化文本，默认统一落在 `C:/Users/18030/Desktop/GPT-files`。
- 不要把这类临时文件写进项目目录、仓库目录或原始数据目录；这样既容易污染工程，也容易把中间垃圾和正式结果混在一起。
- 在 `GPT-files` 下按类型或用途建分类目录，例如 `pdf`、`word`、`latex`、`ppt`、`txt`、`images`、`converted`、`extracted`，保证后续可追踪、可清理。
- 读取完成后，如果这些文件不再需要，应立即删除；即使当次任务暂时保留，项目结束后也要统一清理。
- 如果用户明确要求保留中间产物，也应继续放在 `GPT-files` 体系内，不要因为“先方便一下”而散落回项目树或原始数据目录。

### 核验方法经验

- 中文是否真正写对，应用码点或 `ord()` 抽查，而不是只看 PowerShell 输出。
- 图片是否真正替换，应用哈希或 `word/media` 对照，而不是只看文档标题或图片占位位置。
- 表格与正文是否同步，应用回读方式检查关键段落和关键表格，确认数值口径一致。

### 典型错误与修正

- 错误：先通过 PowerShell heredoc 传入含中文的 Python 脚本，导致写入 `.docx` 的中文变成 `?`。
  修正：改为先用 UTF-8 文件落地脚本，再运行脚本重建文档。
- 错误：初次修改后只看到了终端输出，没有立即确认 `.docx` 内真实 Unicode 内容。
  修正：补做码点检查和文档回读，确认内容不是表层正常。
- 错误：一开始只看段落索引，没有同时检查段落与表格混排顺序。
  修正：增加 block 级遍历后再定位目标区，替换才稳定。

### 复用判断

- 只要任务涉及 Word 文档、LaTeX 源文件、中文写回、Windows PowerShell、批量文本替换、技能体系维护或高价值文件回写，都应优先回忆并复用本文件中的相关经验。
- 只要任务涉及文档读取、格式转换、抽取中间结果或临时缓存落地，也应先复用本文件中的临时目录管理经验。
