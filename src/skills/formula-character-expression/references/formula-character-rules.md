## 1. 对话中出现的公式字符

适用场景：在对话里介绍、说明、解释公式。

基本要求：

- 必须连续给出两个版本：先给“完全渲染版”，再给“LaTeX 版”。
- “完全渲染版”不是只给公式本体，必须完整包含：完全渲染的公式、`其中：`、公式中出现的全部变量及其解释；变量名称也要按最终渲染形态展示。
- “LaTeX 版”也不是只给公式源码，必须完整包含：LaTeX 格式公式、`其中：`、公式中出现的全部变量及其解释；变量名称按目标格式写成 LaTeX。
- 两个版本解释的是同一个公式说明单元，变量覆盖范围应一致。不得因为变量解释已在完全渲染版出现，就省略 LaTeX 版中的变量解释。
- 渲染版必须完全可读，不出现裸露 LaTeX 源码。
- 标注为“完全渲染版”的输出区域里，最终展示内容不得出现 `$` 符号；`$...$`、`$$...$$`、`\(...\)`、`\[...\]` 只属于 LaTeX 版、README 版或内部排版语法，不得作为渲染版正文原样暴露。
- 渲染版解释变量时，直接使用数学字符，例如 `γ`，不要写成 `\gamma`。
- 渲染版的“其中：”变量解释中也不得出现 `$G$`、`$V$`、`$E$`、`$...$`、`\(...\)`、`\[...\]` 这类源码包裹；无角标单符号优先写成可直接阅读的数学字形，例如 `𝐺`、`𝑉`、`𝐸`，LaTeX 源码只放在随后的 LaTeX 版。
- LaTeX 版只在这里判断采用 Word 格式还是 PPT 格式，具体格式要求见第 2 部分。

选择逻辑：

- 如果用户提到 Word、docx、实验报告、论文、论文原理详解、论文公式解读、正式文档、写入文件、正文等，优先使用 Word 格式文件 LaTeX 版。
- 如果用户提到 PPT、PowerPoint、幻灯片、答辩汇报、演示文稿、复制到 PPT、课件等，使用 PPT 格式文件 LaTeX 版。
- 如果只说“给我公式解释”“在对话里展示”“讲一下这个公式”，但没有说明后续写入哪里，优先使用 PPT 格式文件 LaTeX 版。

## 2. LaTeX 版

适用场景：对话中公式后附带的 LaTeX 版，以及写入文档时使用，包括实验报告、论文、论文原理详解、论文公式解读等。

### 2a. Word 格式文件 LaTeX 版

格式要求：

- 公式和变量统一使用 `$...$` 包裹。
- 独立公式单独成行书写。
- 公式后新启一行写 `其中：`。
- 变量解释从 `其中：` 下一行开始逐项书写。
- 每个变量解释统一写成 `$变量LaTeX$：变量解释。`
- LaTeX 版必须覆盖公式中的全部关键变量，不能只给公式源码，也不能只给完全渲染版中未解释过的变量。
- 中文解释文字不需要放进 `$...$`，只有公式字符、变量、上下标、希腊字母、分位数表达等数学部分需要放进 `$...$`。
- 适用于 Word、docx、实验报告、论文正文、论文原理详解、论文公式解读文件。

示例：

```text
$E_{ws} \ge \phi^{-1}_{w0}(1-\alpha)$

其中：
$E_{ws}$：AGV $w$ 到达节点 $\nu_s$ 时的能量下界。
$\phi^{-1}_{w0}(1-\alpha)$：AGV $w$ 当前初始能量随机变量的 $1-\alpha$ 分位数。
$\nu_s=I_w$：当前节点是 AGV $w$ 的初始节点。
$I_w$：AGV $w$ 的初始节点。
```

### 2b. PPT 格式文件 LaTeX 版

格式要求：

- 公式本身使用 `\(` 与 `\)` 包裹。
- 公式后新启一行写 `其中：`。
- 变量解释部分整体使用一组 `\(` 与 `\)` 包住。
- 不要把每个变量单独写成 `\(E_{ws}\)`、`\(w\)`、`\(\nu_s\)` 这种零散形式。
- 在整段 `\(...\)` 内，变量、上下标、希腊字母、分位数表达等数学字符使用 LaTeX 写法。
- 中文说明直接跟在变量后面，和 LaTeX 字符混排在同一个 `\(...\)` 内。
- LaTeX 版必须覆盖公式中的全部关键变量，不能只给公式源码，也不能只给完全渲染版中未解释过的变量。
- 适用于 PPT、答辩汇报、课件、幻灯片、演示文稿。
- 无法判断目标格式时，优先使用这一种。

示例：

```text
\(E_{ws} \ge \phi^{-1}_{w0}(1-\alpha)\)

其中：
\(E_{ws}：AGV w 到达节点 \nu_s 时的能量下界。
\phi^{-1}_{w0}(1-\alpha)：AGV w 当前初始能量随机变量的 1-\alpha 分位数。
\nu_s=I_w：当前节点是 AGV w 的初始节点。
I_w：AGVw 的初始节点。\)
```

## 3. README.md 中的公式字符

适用场景：与代码位于同一文件夹的 `README.md`。

保持 `code-project-rules` 原规则不动：

- 使用 GitHub 可直接渲染的 LaTeX 格式。
- 行内公式使用 `$...$`。
- 独立成行公式使用 `$$...$$`。
- 不使用实验报告正文那种“先写渲染公式、下一行再重复 LaTeX 源码”的双行格式。
- 公式后仍写 `其中：`，并逐项解释公式变量。
- 变量解释统一使用 LaTeX 形式，例如 `$k_1$：变量解释。`
- 变量解释必须覆盖当前公式或公式组中的全部关键符号。

## 4. 简单数学字符与结构化数学内容的强制判定

本节是在前述规则基础上的新增细化规则，不替代、不删除前述“完全渲染版 + LaTeX 版”、Word/PPT 格式选择和 README 规则。

### 4.1 简单数学字符

只有同时满足下列全部条件时，才允许在完全渲染版的正文或变量解释中直接使用 Unicode 数学字符：

- 数学内容仅由一个独立变量、常量、希腊字母或集合符号组成。
- 该符号没有下标、上标、左上角标、左下角标、帽子、横线、波浪线、向量箭头或其他附加结构。
- 该符号不与等号、不等号、集合关系、算术运算符、函数参数或其他数学对象共同组成表达式。

符合条件的示例包括：`𝒜`、`𝐸`、`𝑤`、`𝑡`、`α`、`γ`、`φ`、`ν`。

这里的“单个变量”按数学结构判断，不按它在句子中的位置判断。例如，“AGV 𝑤 的速度”中的 `𝑤` 是无角标的单个变量，可以使用 Unicode；“AGV 的能量下界为渲染后的 `E_w^{\mathrm{min}}`”中的变量带有角标，必须通过数学排版引擎渲染，最终显示时不带 `$` 符号。

### 4.2 结构化数学内容

出现下列任一情况时，必须使用数学排版引擎生成完全渲染版：

- 任意下标，例如渲染后的 `E_{\mathrm{tr,total}}`、`E_{\mathrm{tr},w}`、`x_i`、`\nu_s`。
- 任意上标，例如渲染后的 `x^2`、`P^{\mathrm{max}}`。
- 同时包含上下标，例如渲染后的 `P_w^{\mathrm{max}}`、`\phi_{w0}^{-1}`。
- 带帽子、横线、波浪线、向量箭头或其他修饰，例如渲染后的 `\hat{x}`、`\bar{E}`、`\vec{v}`。
- 包含等式、不等式、集合关系或函数关系，例如渲染后的 `w\in\mathcal{A}`、`E_w\ge E_w^{\min}`、`P_w(t)`。
- 包含求和、连乘、积分、极限、分式、根式、矩阵、分段函数或其他二维结构。
- 由两个或更多数学对象组成的完整表达式，即使每个对象单独看都没有角标。

“其中：”后的变量名称、变量表中的符号、正文中单独引用的符号也必须执行相同判断。位置不会降低排版要求：只要有角标或其他结构，就必须渲染。

### 4.3 最高优先级边界

- Unicode 只负责展示没有任何附加结构的单个数学符号。
- 数学排版引擎负责展示所有带角标或结构的数学内容。
- 渲染后的 `E_{\mathrm{tr,total}}` 不能写成 `𝐸_(tr,total)`。
- 渲染后的 `E_{\mathrm{tr},w}` 不能写成 `𝐸_(tr,𝑤)`。
- 渲染后的 `P_w^{\mathrm{max}}` 不能写成 `𝑃_𝑤^(max)`。
- 渲染后的 `\sum_{w\in\mathcal{A}}` 不能写成 `∑*(𝑤∈𝒜)`。

## 5. 完全渲染版中的具体展示规则

### 5.1 完整公式

- 完整公式使用数学环境排版。
- 独立公式优先单独成行，使上下标、求和界限、分式和矩阵保持真正的二维结构。
- 不得把需要渲染的公式放入 Markdown 代码块，否则公式会显示成源码。
- 标注“完全渲染版”时，只能给读者看到的公式效果；不要把带 `$` 的 Markdown 数学源码放在该区域。需要提供 `$...$`、`$$...$$`、`\(...\)` 或 `\[...\]` 时，统一放入后续“LaTeX 版”。
- 求和或积分的范围必须放在对应运算符的正确上方或下方，不得改写为星号加括号的线性形式。

### 5.2 “其中：”后的变量解释

- 无角标的单个变量直接使用 Unicode 数学字符，例如 `𝑤`、`𝑡`、`α`、`𝒜`。
- 任何带角标的变量使用行内数学渲染，例如渲染后的 `E_{\mathrm{tr,total}}`、`E_{\mathrm{tr},w}`、`P_w^{\mathrm{max}}`；最终展示不得带有 `$` 符号。
- 完全渲染版的变量解释必须按读者看到的最终形态书写，不得把行内 LaTeX 源码包裹当成变量名称输出。`G=(V,E)` 只是无角标图模型公式的示例，用来说明所有公式介绍都要遵守“完全渲染版变量无源码包裹、LaTeX 版变量用 LaTeX”的通用规则；不得理解为只有图模型公式才需要拆分双版本。例如该公式中，`G`、`V`、`E` 属于无角标单符号，变量解释应写作 `𝐺：道路网络对应的图。`、`𝑉：顶点集合。`、`𝐸：边集合。`，不要写成 `$G$：...`、`$V$：...`、`$E$：...`。
- 一个变量解释中如果同时出现无角标变量和带角标变量，分别按各自结构处理，不得为追求形式统一而把带角标变量改成线性 Unicode。
- 中文解释保持普通文本；只有数学部分进入数学环境。

### 5.3 正文中的变量引用

- “AGV 𝑤”“时刻 𝑡”“集合 𝒜”可直接使用 Unicode。
- “AGV 𝑤 的能量为渲染后的 `E_w`”“上限为渲染后的 `P_w^{\mathrm{max}}`”中的带角标符号必须行内渲染，最终展示不得带有 `$` 符号。
- 不因符号只出现一次、位于括号中或紧跟中文而取消数学渲染，正文中所有出现的变量都需要。

## 6. 双版本输出与变量解释的组合规则

- 继续严格保留原有要求：对话中介绍、说明或解释公式时，先输出完全渲染版，再紧接着输出 LaTeX 版。
- 完全渲染版必须包含可直接阅读的完整公式说明单元：公式本体、`其中：`、公式中全部关键变量及其解释。该版本中，无角标单符号使用 Unicode，带角标或有结构的符号使用数学渲染。
- 完全渲染版中的变量解释不承担“提供可复制源码”的任务；不要在变量名外保留 `$...$` 或 `\(...\)`。如果需要源码、Word/PPT 可复制格式或变量 LaTeX 写法，统一放到后面的 LaTeX 版。
- 如果某个界面无法真正渲染公式，仍不得把带 `$` 的源码伪装成“完全渲染版”；应说明当前界面无法显示完全渲染版，然后只给 LaTeX 版源码。
- LaTeX 版必须包含可复制到目标环境的完整公式说明单元：公式源码、`其中：`、公式中全部关键变量及其解释，并继续按前述逻辑选择 Word 格式或 PPT 格式。
- 双版本以一个完整的公式说明单元为单位。完全渲染版和 LaTeX 版都要完整解释变量；区别只在变量和公式的呈现方式，不在解释内容是否省略。
- 如果一次解释多个公式，应按“公式组”或逐个公式建立完整说明单元。无论选择哪种组织方式，都要保证每个公式出现的变量在完全渲染版和 LaTeX 版中都被解释。
- 如果用户只询问一个带角标的变量如何显示，该变量本身也视为结构化数学内容：先显示完全渲染结果，再提供 LaTeX 版。
- README 场景继续遵守第 3 节的既有例外，不重复生成对话式双版本。

## 7. 字体和数学语义规则

- 数学变量默认使用数学斜体，例如 LaTeX 版写作 `w`、`t`，完全渲染后显示为 𝑤、𝑡。
- 花体集合使用 `\mathcal`，例如 LaTeX 版写作 `\mathcal{A}`，完全渲染后显示为 𝒜。
- `tr`、`total`、`max`、`min`、`req`、`rem`、`chg` 等说明性英文角标使用正体 `\mathrm{...}`。
- 角标同时包含说明性文字和变量时，只将说明性文字设为正体。例如 LaTeX 版 `E_{\mathrm{tr},w}` 中 `tr` 为正体，`w` 为变量斜体；完全渲染后不显示 `$`。
- 多个说明性词共同构成一个下标时，统一放入同一个 `\mathrm{...}` 中并用逗号分隔。例如总行驶能耗的 LaTeX 版写成 `E_{\mathrm{tr,total}}`，完全渲染后不显示 `$`。
- 不得为了模仿外观加入没有数学含义的 `*`、下划线、普通括号或其他字符。

## 8. 丰富示例

本节示例只说明排版判断和输出结构的侧重点，不代表只有示例中的变量、AGV 场景、图模型或能耗公式才这样写。所有对话中的公式介绍都必须按第 1 节和第 6 节执行：完全渲染版包含公式、`其中：` 和全部变量解释，LaTeX 版也包含公式、`其中：` 和同一批变量解释。

示例中出现的“渲染后的 `...`”是维护文档为了描述渲染效果而使用的文字占位。实际对话输出时，不得输出“渲染后的”这类占位词，也不得把反引号中的 LaTeX 源码放在“完全渲染版”里；应让公式排版引擎显示最终公式效果，且完全渲染版不出现 `$` 字符。

### 8.1 单个无角标变量

完全渲染版中的变量解释：

```text
𝑤：AGV 的索引。
𝑡：时间变量。
𝒜：AGV 集合。
α：允许的风险水平。
```

这些符号均无角标或其他结构，可以直接使用 Unicode。

### 8.2 只有一个带下标的变量

完全渲染版：

渲染后的 `E_{\mathrm{tr,total}}`

其中：

渲染后的 `E_{\mathrm{tr,total}}`：所有 AGV 的总行驶能耗。

LaTeX 版按目标环境提供 `$E_{\mathrm{tr,total}}$` 或 `\(E_{\mathrm{tr,total}}\)`。不得输出 `𝐸_(tr,total)`。

### 8.3 求和公式

完全渲染版：

渲染后的独立公式 `E_{\mathrm{tr,total}}=\sum_{w\in\mathcal{A}}E_{\mathrm{tr},w}`，求和范围、下标和集合符号均由数学排版引擎显示，屏幕上不出现源码定界符。

其中：

渲染后的 `E_{\mathrm{tr,total}}`：所有 AGV 的总行驶能耗。
渲染后的 `E_{\mathrm{tr},w}`：AGV 𝑤 的行驶能耗。
𝑤：AGV 的索引。
𝒜：AGV 集合。

判定说明：两个能耗变量带下标，必须渲染；`𝑤` 和 `𝒜` 是无角标单符号，可以使用 Unicode。

### 8.4 同时包含上下标

完全渲染版：

渲染后的独立公式 `P_w(t)\le P_w^{\mathrm{max}}`，函数、下标和上标均由数学排版引擎显示，屏幕上不出现源码定界符。

其中：

渲染后的 `P_w(t)`：AGV 𝑤 在时刻 𝑡 的充电功率。
渲染后的 `P_w^{\mathrm{max}}`：AGV 𝑤 允许的最大充电功率。
𝑤：AGV 的索引。
𝑡：时间变量。

### 8.5 分式公式

完全渲染版：

渲染后的独立公式 `T_w=\frac{E_w^{\mathrm{req}}-E_w^{\mathrm{rem}}}{P_w^{\mathrm{chg}}}`，分式、上下标和说明性角标均由数学排版引擎显示，屏幕上不出现源码定界符。

其中：

渲染后的 `T_w`：AGV 𝑤 所需的充电时间。
渲染后的 `E_w^{\mathrm{req}}`：AGV 𝑤 的目标能量。
渲染后的 `E_w^{\mathrm{rem}}`：AGV 𝑤 的剩余能量。
渲染后的 `P_w^{\mathrm{chg}}`：AGV 𝑤 的充电功率。
𝑤：AGV 的索引。

### 8.6 概率分位数和希腊字母

完全渲染版：

渲染后的独立公式 `E_{ws}\ge \phi_{w0}^{-1}(1-\alpha)`，下标、逆函数上标和分位数表达均由数学排版引擎显示，屏幕上不出现源码定界符。

其中：

渲染后的 `E_{ws}`：AGV 𝑤 到达节点 `\nu_s` 的渲染结果所表示的节点时的能量下界。
渲染后的 `\phi_{w0}^{-1}(1-\alpha)`：初始能量随机变量的 `1-\alpha` 渲染结果所表示的分位数。
渲染后的 `\nu_s`：节点序列中的第 𝑠 个节点。
𝑤：AGV 的索引。
α：允许的风险水平。

判定说明：`α` 和 `𝑤` 单独出现时可使用 Unicode；渲染后的 `\nu_s`、`E_{ws}` 和分位数表达式包含角标或运算结构，必须渲染。

### 8.7 正文混排

正确示例：

```text
对每个 AGV 𝑤，使用渲染后的 `E_{\mathrm{tr},w}` 表示其行驶能耗，并用渲染后的 `P_w^{\mathrm{max}}` 表示最大充电功率。
```

错误示例：

```text
对每个 AGV 𝑤，使用 𝐸_(tr,𝑤) 表示其行驶能耗，并用 𝑃_𝑤^(max) 表示最大充电功率。
```

## 9. 禁止形式与渲染失败处理

以下线性模拟形式一律禁止：

- `𝐸_(tr,total)`
- `𝐸_(tr,𝑤)`
- `𝑃_𝑤^(max)`
- `φ_(w0)^(-1)`
- `∑*(𝑤∈𝒜)`
- 使用普通下划线或括号假装上下标的任何类似形式

如果当前界面不支持数学公式渲染：

- 明确说明当前环境无法显示完全渲染版。
- 仍提供标准、完整、可复制的 LaTeX 源码。
- 不得把结构化数学内容降级为不准确的 Unicode 线性模拟。
- 不得声称 `E_(...)` 或 `∑*(...)` 与二维数学排版等价。
